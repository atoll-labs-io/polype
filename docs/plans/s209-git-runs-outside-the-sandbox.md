## The pivot
Leaving git's global ignore out of the governing list, rather than moving the masks to a file of their own, makes the run hold whoever appends to that file. Ways it could be wrong:
- **The writer rewrites rather than appends** (drops the masks): the run stays valid but every lane looks dirty to the lead. Compare the kept results of the next real run: `git status` lines naming `.zshrc`, `.idea`… in the stream.
- **The ignore governs more than it seems**: an entry hiding `src/` would make an agent miss a file to commit. The grade reads commits and files, never `git status`, so the run is still graded on what landed; the reviewer checks that no predicate of `evals/real/grade.sh` reads `git status`.
- **`Bash(git *)` does not match the forms the method uses** (`git -C <path> …`, `git -c …`) in the Claude Code in use: git commands would be refused as before, which the stream shows as `permission_denied` on `git`. Compare with the permissions page of the Claude Code docs before the next real run.
- **The four deny rules refuse too much or too little.** Too much: if Claude Code matched rules without case, `Bash(git -c *)` would refuse every `git -C <path>` that s210 makes the method write, and no lane would open; a commit message holding ` -c ` is refused too. Too little: a leading `VAR=… git …` or a form the wildcard misses passes; `Bash(git * --config-env*)` exists because `Bash(git --config-env*)` missed `git -C <path> --config-env=…`. Both show only on a real run, as `permission_denied` on a `git -C` line or a `-c` that went through; check the docs' matching rules first.
