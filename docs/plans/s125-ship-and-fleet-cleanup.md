## The pivot
The story hinges on the ship-order reading of task 4: the review order decides which ship **starts** first, and a ship ends on its landing **or** on its stop. Ways it could be wrong:
- Under `Merge mode: local` with an effective `human`, a "Not now" lands nothing and ends that ship (`po-ship.md:80`). The next ship then starts and may land first, which is exactly what "which ship starts first, not which story lands first" allows. If a reviewer reads "Not now" as a ship that must block the queue, the sentence is wrong. Compare with `po-ship.md:80-81`.
- Under `automatic`, a ship that waits for `ci` has not ended: the next one must not start before the merge is proven. The appended sentence ties the end of a ship to Step 3's proof, so read it against `po-ship.md:77,84`.
- The shared sentence must not weaken `in the order the reviews passed` (`tests/fleet-wiring.test.sh:38`). It adds a clause and removes none.

There is a second hinge, in task 10 (b): the short-subject mutant must reach the test through `HOOK="$METHOD/hooks/po-session.sh"`, which is computed when the file is sourced. `run_against` sets `METHOD` first (`tech-choice-backstop.test.sh:20-22`), so the mutant is what the test runs; check that the real-method run passes before trusting a red mutant.
