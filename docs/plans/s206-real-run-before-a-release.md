# Plan — s206-real-run-before-a-release

[Story](../stories.md) · [Research](../research/s206-real-run-before-a-release.md)

Branch `story/s206-real-run-before-a-release`. Read the research first; this plan builds on it without repeating it.

## Story
`bin/po-eval real` builds the journey repository for a real lead, launches it through `po run`, grades every run by scripts, and compares control arms declared by files; it lists the rules whose removal moved no rate and retires none. Criteria, sorted as `docs/direction.md` asks:
- read by a script, oracle test: `real_run_drives_the_journey_repository`, `a_run_is_graded_by_scripts`, `suite_never_pays`, `any_rule_can_have_a_control_arm`, `a_rule_that_moves_nothing_is_reported`;
- half script, half model: `m21_bis_rules_have_their_cases` — the oracle checks that each of the 28 rules has a known case that builds, or a reason; whether a case really exercises its rule is judged in review;
- read by a person only: `release_names_its_real_run` (`docs/ci.md`, `docs/evals/`), judged in review.

## Decisions of the owner (2026-11-23)
1. **d-0057 → [ADR-0133](../decisions/ADR-0133-combien-de-passages-payants-fondent-le-retrait-d-une-regle.md), O1.** Two stages, rule by rule, on demand: 3 runs per arm, a rule that moved by at least 1 is kept; one that did not is measured again at 13 per arm and proposed for retirement only if the gap stays under 2. Nothing is measured until someone proposes a retirement; one journey run, with no arm, before each release. In code: the margin is 1 up to 5 runs per arm, 2 above (task 4).
2. **d-0056 → [ADR-0134](../decisions/ADR-0134-un-passage-reel-se-lance-devant-une-personne-dans-une-configuration-confinee.md), C1.** A permission allowlist in the temporary config (`git`, `bash`, `sh`, `jq`, the config's `po`, `.polype/hooks/*`, file tools limited to the run folder, the Agent tool; web tools, `curl`, `claude` denied), `--permission-prompts none`, `HOME`, `TMPDIR` and the config in the run folder, doubles for `gh curl glab tea task claude`, no forge token, `--max-budget-usd` per session, never `--fallback-model`. **A real run is for a person who launches and watches it**: the confirmation is asked on a terminal; standard input not a terminal (`[ -t 0 ]` false) → `needs a terminal`, `nothing run`, exit 2, before any build or call; no option skips the confirmation. Limit, stated in ADR-0134 and in the docs: the lead and the planner are not bounded; an allowed `git -C` or a redirection reaches any path the user can, and any agent can read its own environment, login included. An unattended or scheduled run needs a sandbox first, through a new ADR.
3. The login comes from `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN`, as `--control` already does (`bin/po-eval:196-199`); only its name is ever printed.
4. **d-0060 → [ADR-0135](../decisions/ADR-0135-gh-entre-dans-la-liste-de-permissions-d-un-passage-reel.md), option a (fix run 2).** `gh` joins the allowlist: the run's `gh` double comes first on `PATH` and no forge token is set. It supersedes ADR-0134 on that point only.

The oracle meets the interface only; a paid launch goes through `script -qec … /dev/null` (util-linux) so the command meets a pseudo-terminal, as a person's would, and the answer echoed by the terminal is one more output line. ## The interface the oracle fixes
`po-eval real [--repeat N] [--sessions S] [--model M] [--budget USD] [--arm <name|file.arm>]… [--keep] [--record] [case…]` (default case `journey`, N 1, S 3, budget 10); `po-eval real --list | --rules | --build <case> <dir> | --build-all <dir>`. `--arm <name>` reads `evals/arms/<name>.arm`; a path ending in `.arm` is read as is. Output lines, exactly: `<c> cases × <n> repetitions[ × <k> arms] = <T> paid runs of claude -p` then `Continue? [y/N]`; `results: <dir>`; `session: <8 chars>`; `story <id>: landed — actions: <list> — fix loops: <n>` or `story <id>: not landed — stage: <stage or none> — waiting: <ids or none>`; `case <case> run <n>[ (<arm>)]: pass|fail`; `<case>: <p>/<n> passed` or `<case>: rule <p>/<n> | control <arm> <q>/<n>[ | control …]`; `lowered: …`, `raised: …`, `moved no rate: <arms or none>`. Actions, in this order, are those whose file the landed commit holds: `research` (`docs/research/<id>.md`), `design` (`docs/designs/<id>/`), `plan`, `execute` (`docs/verif/<id>.md`), `qa` (`docs/qa/<id>/`), `review`, then `ship`; fix loops are `trust.fix_loops` of `po state --all`.

## The pivot
`po run` launches a foreground `claude -p` through `PO_CLAUDE`, so the real run crosses the same bounds check, lock and command choice a person's `po run` does, with no change to `po/`. How it could be wrong: `po run` holds its launch lock for the whole session (stale after 600 s, `mod.rs:43`) — harmless here, since nothing else launches in a throwaway repository, but compare with `mod.rs:212-233` if a run ever starts two; `po state`'s `session.running` reads `[]` from the wrapper, so it says `false` during the run — the grader never reads it; Claude Code may load hooks or permissions differently under `-p` than under `--bg` — the first real run's `bounds` line and `po-bounds` refusals in the transcript show it.
