## Test strategy
Three bash tests, well within `Test budget` 25, all at the one layer that exists here (the profile file read by `po-lint` and checked against its source). The two acceptance-criterion tests carry the criteria's names. The grounding test answers "written from the starter at a named commit": deleting a fact's link to the source (a made-up path, a wrong licence, a wrong script) turns it red, which a lint-only test would not. Not tested: the behaviour of `npm run web` and `npx jest` themselves — they are documented as not run, as in hono-api.

## The pivot
Two linked choices, both in ADR-0062. (1) **Source = `sdk-57` head, not `main`**: wrong if `create-expo-app`'s default moves to SDK 58 soon — then the profile describes yesterday's starter, which is fine for a named commit but must be redone. (2) **`Test: npx jest` for a template that ships no test runner**: wrong if a reviewer reads the criterion as "the starter's own Test command"; then the honest answer is `Test: —` and a corrected criterion, and the story goes back to a person. The profile must say plainly that `npx jest` fails until `jest-expo` is installed, so `/po-setup` users are not misled.
