## Story
A read-only `qa` subagent, dispatched by `/po-qa`, walks in a browser the screens the story's diff touches and each visible acceptance criterion, and writes a report with captures under `docs/qa/<id>/`. It never fixes. `po-bounds` gains a `qa` mode; the settings gain `Dev` and `QA stage`; `design-doctrine` carries the browser contract once. Criteria: `qa_writes_are_bounded_by_the_hook`, `qa_scope_comes_from_the_diff_and_the_criteria`, `qa_report_has_steps_evidence_and_status`, `qa_stops_without_a_browser_or_a_dev_command`, `setup_asks_for_dev_and_qa_stage`, `browser_contract_is_written_once`, `help_lists_po_qa`. Cycle wiring, `po-gate qa-current` and the evidence commit are s52's.

## The pivot
The QA reaches the session's browser only because its frontmatter has **no `tools:` line** and removes Edit by `disallowedTools` (ADR-0026). Ways it can be wrong:
- A `tools:` line added later silently cancels `disallowedTools` (Claude Code ignores it then) — the test refuses any `^tools:` line, and the hook still refuses `qa:Edit` (`po-bounds.sh:162`), which is why the matcher keeps `Edit`.
- A Claude Code version that does not honour `disallowedTools` for subagents: the agent would hold Edit, the hook would still refuse each call. Compare against the agent field list read in the 2.1.292 binary (research, Verified interfaces).
- Inherited tools write files the hook never sees (browser screenshots, a filesystem MCP server): accepted in ADR-0026; the reviewer should check that the story claims nothing more than "Write and git are bounded".
Second hinge: the git allowlist. Too narrow costs a reworded command; check it against what `## The walk` actually needs (`diff`, `rev-parse`, `status`).
