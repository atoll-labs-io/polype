## Story
A project chooses `Project CLAUDE file: absorbed` (ADR-0086, the default `/po-setup` writes) or `kept` (its `CLAUDE.md` and `CLAUDE.local.md` stay, the root `CLAUDE.md` starts with `@AGENTS.md`, the pre-commit and `po-session` let them be). A missing line changes nothing and is named. Criteria: `setting_has_two_values`, `kept_keeps_and_imports`, `missing_setting_changes_nothing`, `adr_records_the_choice`.

## The pivot
Only the exact values `absorbed` and `kept` act; everything else — no line, no `AGENTS.local.md`, a typo — is "missing", which touches nothing and refuses at commit. Ways it could be wrong:
- One of the three readers parses differently (the spaces inside the name, trailing spaces, value read from the absorbed-notes section lower in the file): compare the three sed forms; each takes the first match only, and the settings block precedes any `## Notes moved from …`.
- `kept` writing `CLAUDE.md` in a way `remove` cannot undo: the round trip in `test_kept_keeps_and_imports` must restore the notes file without the import and delete the created one.
- An existing test still assuming unconditional absorption (fixture without the line) left green by accident: grep `tests/` for `CLAUDE.md` fixtures with an `AGENTS.local.md` lacking the line.
