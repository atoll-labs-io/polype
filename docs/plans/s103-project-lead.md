## Story
The main session of a Polype project is its project lead (ADR-0076). It leads framing in conversation when it is missing, then runs `/po-drive` wave after wave until the milestone ends, never writing a story's code; it answers the question asked first. A `SessionStart` hook, `.polype/hooks/po-session.sh`, gives it the project state read from disk and git; the installer wires it into the project's `.claude/settings.json` with `jq`.

Criteria: `rules_name_the_project_lead`, `lead_answers_before_driving`, `session_hook_reports_state_read_only`, `session_hook_silent_outside_polype`, `installer_wires_the_session_hook`, `help_says_no_command_needed` — each the name of a test function in `tests/project-lead.test.sh`.

## The pivot
The hook is trusted as the lead's picture of the project, so everything hinges on **`po-session.sh` deriving the same state `/po-drive status` derives, from local disk and git only**. Ways it could be wrong:
- **The presumed PR.** Without the forge, a pushed `story/<id>` with a favourable review under `human` is read as "waiting"; a PR closed or merged on the forge but not fetched still reads that way. Compare with `po-drive.md:64-65`: the line says "presumed" and "the forge was not asked", and the lead confirms with `/po-drive status` before acting.
- **Path matching of lanes.** `git worktree list --porcelain` prints absolute, symlink-resolved paths; `<top>/<Worktree root><id>` built from a relative setting must be compared on the same footing (resolve `top` with `pwd -P`), or every lane reads as an orphan. Test 3 covers a real `git worktree add` under a temp dir.
- **The jq merge.** A filter that rebuilds `.hooks` instead of updating `.hooks.SessionStart` would drop the user's other events; test 4 keeps a foreign `SessionStart` entry and a `permissions` key to catch it.
