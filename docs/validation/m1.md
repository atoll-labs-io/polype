### Preuve de morsure (extrait de la revue)

| # | Neutralisation | Tests rouges |
|---|---|---|
| M1 | Comparaison d'expiration `>` → `>=` | 1 |
| M2 | Contrôle d'expiration supprimé | 1 |
| M3 | Plafond `Math.min` supprimé | 1 |
| M4 | `Math.floor` → `Math.round` | 1 |
| M5 | `Object.hasOwn(COUPONS, code)` → `code in COUPONS` | **0** |
| M6 | `total` ne soustrait plus la remise | 1 |

**M5 est un vrai trou trouvé par la méthode.** Le test « code inconnu » utilise `'NOPE'`, qui échoue avec ou sans la garde. Le code est correct aujourd'hui, mais si quelqu'un « simplifie » la garde, `total(items, { coupon: 'toString' })` renverra silencieusement `NaN`. La revue l'a classé majeur, ce qui a autorisé le ship et laissé la correction au cycle suivant. C'est exactement le cas que la doctrine décrit : un test qui nomme une règle sans l'exercer, invisible à la lecture des assertions.

## Enseignements pour la suite

- **Sévérité à affiner (M2)** : une garde dont la chute corromprait silencieusement un montant, sans aucun test pour la protéger, mériterait peut-être le niveau critique. L'échelle actuelle juge le code livré, pas le filet de sécurité. À discuter avant d'en faire une règle.
- **Headless** : la liste d'outils autorisés a suffi, aucun blocage. C'est un point de départ pour les workers de la flotte (M3).
- **Décisions produit prises par le plan** (expiration inclusive jusqu'à 23:59:59 UTC, `total` qui lève une erreur plutôt que d'ignorer le coupon) : avec la validation autonome, personne ne les a relues. C'est un argument pour la validation groupée par vague en M3 (ADR-0014) plutôt que pour l'autonomie totale.
